# pm-liquid：流动性优先的事件合约研究

## 每次任务收尾

完成或中断都检查本轮文件与程序。删除本轮确认的一次性下载、临时脚本、测试缓存；仅停止本轮启动且已不需要的子进程/服务器，关闭本轮专用浏览器标签页，不关闭用户已有应用或其他任务。正式产物、用户记录及所有 `.mimosa/` 保留；归属不明不删。命令优先 `python -B`，盘口只在本轮内存复用。最终简报删除/保留/归档及仍运行项；不能把规则说明当成已执行清理。

## Overview

扫描 Polymarket 与 Kalshi 上**当下真正可成交**的事件合约，用独立证据解释与市场情绪的偏离，给出带入场价与失效条件的候选。价格是情绪基线，ask 是执行成本；不估计概率，不宣称校准。

## 先说人话（默认表达）

用户要的是“买什么、挂多少、什么时候撤”，不是扫描器字段。默认按这个顺序：

1. **第一句先给结论**：有没有值得挂的单；没有就直说“没有合格单”，并说清是价差太宽、证据不够，还是已开赛、流动性太薄。
2. **默认只给一张挂单表**：买什么｜挂单价｜20 份成本｜什么情况撤。平台、周期和方向写在“买什么”里，例如“Kalshi 10 月 CPI >0.3% · 买 NO · 11-10 收盘”。
3. **盘口、价差、成交量、规则和跨平台对比放表后 3–5 行**，不塞进每一行；用户追问再展开完整盘口和计算。
4. **解释“市场为什么这么定价”**：直接说“市场给 X，独立证据说 Y，差在哪”；没有独立证据就只描述市场基线，不编概率。
5. **术语第一次出现就翻译**（见下方“术语翻译”）：不要把 VWAP、longshot、feeSchedule 直接丢给用户。
6. **不把“状态/盘口/依据”三件套当默认**：那是完整核对版的列；默认表只保留能执行的四列。
7. **体育盘已开赛/进行中默认不参与**，除非能核验实时比分、图池或伤停等硬信息；不要拿“盘口在动”当方向。
8. **结论必须能执行**：给具体挂单价、份数和撤销条件；只写“关注”不算完成。

## 默认值

- 平台：both。Polymarket 标签 `sports,economics,politics,finance`；Kalshi 系列 `KXNBAGAME,KXNFLGAME,KXNHLGAME,KXCPI,KXPAYROLLS,KXFED,KXBTCD`（系列代码会变，`--series` 覆盖）。
- 执行检查：两侧真实 ask/bid，20 份完整成交；价差 ≤5c；价格带 10–90c（longshot 屏幕，`--tail` 放开）。NO 侧盘口默认只取成交量前 4 个（`--no-books` 调整）。
- 已收盘（endDate 已过）自动剔除；周期按行标注（日内/1-7天/1-4周/1月+）。

## 流程

1. 无上下文先问一个四选一问题：高胜率 / 均衡（推荐）/ 高赔率（加 `--tail`）/ 直接扫（默认均衡）。已有偏好不重复问。
2. 跑 `python -B scripts/scan.py --top 8`。指定事件用 `--query`（在抓盘口前过滤）；只要一边用 `--platform`；结构化字段用 `--json`，需要减少输出时加 `--json-limit 8 --compact-json`。耗时取决于网络，不承诺缓存命中或固定完成时间。
3. 逐条读规则：YES 条件、截止时刻（时区）、指定结算源、平局/取消/改期/修订。标题不算规则；读不清标“规则待核”，不进主表。
4. 找独立证据解释偏离（官方赛果/发布日程/公告生效时点/指定取价所）。没有证据就只描述市场基线，不写概率。
5. 执行评估：默认被动限价；吃单要显式理由并计 taker 费；费用逐市场查（未知≠0，只给毛值）；按份数核对 ask 阶梯完整成交。
6. 输出候选表，然后说明理由、缺口和已查范围。

## 硬规则

- Longshot 屏幕：默认不主动买 <10c、不追 >90c（Kalshi 全样本 <20c 跑输、>80c 跑赢）。
- Maker 优先：入场价写在价差内有依据的位置；不机械减 2–5¢，不挂无依据远端；成交后重读证据。
- 24h 成交只作附注：Kalshi 按 $1 名义计且串关膨胀，临开赛/刚结束的赛事都会失真；可执行性以当下盘口为准。
- 不用中价、最新成交价、`1-YES bid` 当可成交价；不用未排序盘口首项；部分成交不当整笔。
- 不把挂单占比、成交量、买盘深度当胜率或情绪概率。
- 跨平台价差只在同事件同结算口径下讨论，且为非原子两腿，写“条件观察”，不写“无风险”。

## 输出

默认中文，先结论后表格。默认 3–5 行，最多约 12 行；纯观察单列，不冒充推荐。

### 默认：一张挂单表

| 买什么 | 挂单价 | 20 份成本 | 什么情况撤 |
|---|---|---|---|
| 平台·对象·周期·方向 | 具体限价；注明“可吃”还是“只挂” | 约 $X（容量不足写实际份数） | 一句可核对、可执行的失效条件 |

表头或表下注明报价时间（UTC）。价差、完整 ask 阶梯、24h 量、费用与跨平台对比放表后备注；用户没问就不展开。

### 完整核对版（用户要细节或需要留证时）

默认 3–6 行、最多约 12 行。列：状态（当前可考虑/等待限价条件/不参与）｜对象·周期（收盘）｜方向｜盘口（两侧 ask·bid·价差·20份容量）｜入场参考→可挂限价+一句失效｜把握/依据（来源与方法）。报价带时间戳。模棱两可的候选删除或降观察区并写触发条件；观察单列不冒充推荐。用户给本金与风险预算后才算金额，否则只给单位风险示例。

### 术语翻译（第一次出现就用中文解释）

| 词 | 大白话 |
|---|---|
| YES / NO | 买“会发生” / “不会发生”；每份到期结算 $1 |
| bid / ask | 盘口最高买价 / 最低卖价；ask 是你现在买进的成本 |
| 价差 | ask − bid；越窄越容易成交，默认超过 5¢ 不追 |
| VWAP | 按计划份数吃掉多层挂单后的平均成交价，不是第一档价格 |
| longshot | 低价冷门合约（默认 <10¢ 不主动买）；高赔率模式才放开 |
| maker / taker | 挂单等别人成交 / 直接吃现成卖单；taker 通常有手续费 |
| Kalshi | 美国 CFTC 监管的预测市场交易所，美元计价、每份 $1；24h 量按 $1 名义计，别当概率 |
| Polymarket | 加密 USDC 计价的预测市场，全球用户；体育/政治盘常见 |
| 24h 量 | 只是参考；Kalshi 会被串关放大，临开赛/刚结束都失真，可执行性看当下盘口 |

## Resources

- `scripts/scan.py`：只读扫描（`--help` 看全部参数；`--query` 指定事件；`--tail` 高赔率；`--json` 保留完整默认行字段）。盘口只在单次扫描内用完整 token 键内存复用（并发同 token 仅请求一次），下轮重新取数；不读写 `scripts/.cache/`，不自动删除既有缓存。使用 `python -B` 避免解释器写字节码。
- `--json-limit N` 仅截断 JSON 行数（0 合法），不缩减取数范围；`--compact-json` 仅省略每行 `rules`/`question` 并压缩空白，须与 `--json` 一起使用。省略规则后不可凭该输出确认结算口径。JSON 保留 `elapsed_s`/`rows`，新增 `total_rows`/`returned_rows`/`errors`/`completed_at`。
- `yes_book_sampled_at` / `no_book_sampled_at` 是相应盘口请求成功返回时的 UTC 客户端采样时间；未取或失败为 null，不冒充交易所报价时间。`quote_sampled_at` 是 PM 事件列表 / Kalshi 市场列表返回时点；`completed_at` 只是整轮完成时点，不替代逐项采样时点。
- `references/flow.md`：研究流程、证据类型、输出模板。
- `references/playbook.md`：longshot/maker-taker/成交量口径/跨平台比价/分类打法/常见错误。
- `scripts/pm_common.py`：共享取数与订单簿工具（勿改行为）。
- 天气与逐日最高/最低温档位用 `pm-weather`；其他天气仅按需研究，不承诺专用模型覆盖。

## 预算

目标单轮扫描 ≤60s（不是硬超时；底层请求含重试，网络故障可能超时）；同轮复用内存盘口，不重复拉全量；面向用户只回显表格与统计行，不直接堆 JSON。候选不足时放宽门槛并注明放宽项，不无限扫描；报告实际已查范围与合格数，未覆盖不等于市场无机会。

## 错误处理与验证

- 保留安装版 `_safe` 的 `(result, error)` 约定，汇总发现接口、事件标题与盘口错误至 stderr；JSON 的 `errors` 也包含相同信息。
- 所有市场发现请求均失败时退出码 1、不输出报告；至少一个发现请求成功则退出码 0（包括成功但空结果、关键词无匹配或过滤后无候选）。不能把“有错误且无候选”等同于“全部数据源失败”。单个平台异常也会汇总。
- 部分失败时说明覆盖不完整，立即告知用户缺失源；盘口失败/未取不可当作已验证可成交。扫描不承诺遇到首个网络错误就中断其余请求。
- 永久离线测试：`python -B -m pytest -p no:cacheprovider tests -q`。不写 pytest 缓存；测试仅模拟公开接口响应，不证明实网连通性、真实延迟或全面市场覆盖。
