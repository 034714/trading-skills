# pm-liquid 研究流程（agent 侧）

天气尤其逐日最高/最低温档位研究用 `pm-weather`；本 skill 管流动性好的事件合约（体育、宏观数据、政治大事件、加密价格），默认考虑挂单执行。推文计数、奖项票房不属于天气 skill，也不据此承诺本 skill 已有这些类别的专用概率模型。

## 1. 无上下文时先问一个问题

用 AskUserQuestion，一次四选一：①高胜率（1–7 天深盘，硬证据，接受低赔率）②均衡（推荐）③高赔率（深盘里找低价条件单，`scan.py --tail`）④直接扫（默认：全周期、流动性优先、均衡）。用户已有明确偏好不重复问。

## 2. 扫描（时间预算 ≤60s，token 预算：脚本输出只回显表格）

```bash
python scripts/scan.py --top 8                 # 默认 both，首次约 40s，缓存命中约 20s
python scripts/scan.py --query "Lakers"        # 指定事件，跨平台同看
python scripts/scan.py --tail --top 8          # 高赔率模式：放开 10–90c 屏幕
python scripts/scan.py --platform kalshi --series KXCPI,KXPAYROLLS,KXFED
python scripts/scan.py --json                  # 结构化字段（含 rules 摘要）
python scripts/scan.py --no-books 6            # NO 侧多取几个盘口
```

- 默认标签：Polymarket `sports,economics,politics,finance`；Kalshi `KXNBAGAME,KXNFLGAME,KXNHLGAME,KXCPI,KXPAYROLLS,KXFED,KXBTCD`。系列代码会变，用 `--series` 覆盖；不知道有哪些系列时按需扩展，不做全站拉取。
- 已收盘（endDate/close_time 已过）在取 Top 之前剔除；候选不足时放宽 `--max-spread`/`--shares` 或加 `--tag`，并在输出注明放宽了哪项。
- Polymarket 的 `endDate` 常是结算截止，不一定是开赛时间；体育盘以标题/规则中的比赛时间为准。Kalshi 的 `close_time` 更接近最后交易时间。Kalshi 费用列显示 `?` 不是零，按系列费率页核对。
- 24h 成交列只是参考：Kalshi 按每份 $1 名义计、串关占比高，刚结束的赛事也带着成交量但盘口已空；临开赛的赛事可能盘口深而 24h 数字小。可执行性以当下订单簿为准。

## 3. 逐条读规则（表格之前）

每条候选确认：YES 成立条件、截止时刻（写时区）、指定结算源与页面、平局/取消/改期/修订如何处理、取整与精度。标题不算规则；Kalshi 看 `rules_primary`，Polymarket 看市场 description。读不清就标“规则待核”，不进主表。

## 4. 独立证据（解释偏离，不是复述价格）

- 体育：官方赛果页/赛程、伤病与轮换、历史同对阵；进行中比赛注意“新闻落地后的短窗口”（进球、罚下、数据公布后盘口常慢半拍）。
- 宏观：官方发布日程（时区！）、预期值/前值、季节与基期；只引用可追溯的发布方。
- 政治：官方公告“何时算正式生效”、民调聚合与其历史误差。
- 加密价格：指定交易所、取价时刻、是否含某一时段均价。
- 市场报价是情绪基线：偏离要写“市场给 X，独立证据说 Y，理由是什么”；没有独立证据就不写概率，只描述市场基线。

## 5. 执行评估

- 默认被动限价（maker 侧）：先看两侧真实 ask/bid 与 20 份 VWAP，入场价写在价差内、有成交依据的位置，不机械减 2–5¢，不挂到无依据的远端；未成交就是不成交，成交后重读证据（变便宜常是新信息）。
- 主动吃单要显式理由（新闻窗口、可接受滑点），并计入 taker 费。
- 费用逐市场查：Polymarket 看 `feeSchedule`（未知≠0；2026-03-30 起多品类收 taker 费、maker 有返利、地缘政治类免费）；Kalshi 按系列费率页核对。未知费用只给毛值。
- Longshot 屏幕（默认开）：不主动买 <10c，不追 >90c；要高赔率时才 `--tail` 并明示。
- 容量：按计划份数检查 ask 阶梯完整成交；深度不够就降容量或挂等，不把部分成交价当整笔价。

## 6. 输出（果断、有针对性的表）

默认 3–6 行、最多约 12 行。每行必须能执行：状态（当前可考虑/等待限价条件/不参与）、对象·周期、方向、盘口（本侧 ask·bid·价差·容量）、入场参考→可挂限价+一句失效条件、依据（来源与方法）。模棱两可的候选删掉或降观察区并写清触发条件；观察区单列，不冒充推荐。周期分层写在对象列（日内/1-7天/1-4周/1月+）。

## 7. 收尾

- 报价带时间戳；隔了一段时间重扫前先说明旧价可能失效。
- 用户给了本金和风险预算才算金额；否则只给单位风险示例，不算仓位。
- 同事件多平台都读过才谈价差；结算口径不同不能混。
