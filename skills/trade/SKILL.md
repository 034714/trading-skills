# trade — 条件方案与行情研究

## 不可跳过的边界

- 默认只读，不下单、不调用私有交易接口，不收集密钥、不读写用户账本。公开发布此技能不代表授权交易。
- **先输出条件挂单卡，再给简短理由**。数据不足时卡片写“等待/研究草案”，不以均线排列替代买卖信号。
- 未知本金、风险预算、持仓与账户计价币时，不假设本金或风险比例，不给可执行仓位。不得擅自修改用户风险上限。
- 均线、ATR、RSI、摆点、资金费率、OI、多空比仅为描述，不提供胜率保证。不能单凭 IV/RV 差额推导便宜、昂贵或买卖优势。
- 止损触发和平仓请求均不保证成交；跳空、滑点、流动性与平台故障可使损失超过预算。名义杠杆不是强平安全距离。
- 不以无证据的固定 3× 阈值拒绝；可使用用户明确设置的风险/杠杆上限。超限应降低风险敞口或等待，**不为满足杠杆而缩窄结构止损**。
- 期权仅展示真实合约候选，不生成可执行卖方组合。中性状态不等于卖波动；不输出裸卖，不用“加保护腿”代替完整风险定义。
- 快照字段（现价、24h、资金费率、OI、多空比）是公开接口瞬时数据，非逐笔核验；只用于描述市场状态，不是趋势分析或信号。

## 工作流

1. 明确方向假设、入场触发、失效价、时间有效期、产品类型，以及用户提供的本金与风险预算；缺项就列为待确认，不填造数字。
2. **一条命令拿双标的全量上下文**：`python scripts/crypto_ctx.py --json`（默认 BTC+ETH）。输出含已完成K线指标（EMA20/50/200、Wilder RSI14、ATR14、30日RV、90日区间、右侧确认4H摆点）、现价/24h/资金费率/OI及24h变化/多空比快照、最近到期 ATM IV 与期权候选。更多标的用 `--symbols BTC,ETH,SOL`（最多4个）。**不要再为现价、资金费率或 OI 另写临时脚本**。最新已完成日线收盘价不是实时现价，回复时先注明快照时点。
3. 山寨币筛选：追加 `--scan`（默认 SOL,BNB,XRP,DOGE,ADA,AVAX,LINK,LTC；`--scan-list` 自定义，最多12个）。输出是描述性状态行（RSI、均线排列、距EMA50/200、90日区间位置、费率、标记），**只是“值得细看”的名单，不是信号**；对入围标的先跑 `--symbols <标的>` 完整分析，核查上市规格、流动性与事件后再谈计划。
4. `--auto` 按日线均线状态生成条件情景（震荡列双向备选而非预测）；用户已给方向、入场与止损时用 `--bias long --entry <价格> --stop <失效价>`。`--tranches N`（默认3，1–5）输出等权分批阶梯：批次按 0.5×ATR14 间隔向失效价方向排列，自动剔除距失效价过近（<25%止损距离）的批次，R目标与仓位示意按均价计算；`--tranches 1` 退回单点入场。分批不改变失效价；**总风险预算必须覆盖全部批次**，任何一批成交都不增加预算。加 `--equity <本金> --risk-pct <百分比>` 才有仓位示意，`--max-leverage <上限>` 可选。
5. 期权适配：脚本给出最近到期 ATM IV 与 30日RV 的描述性比较（±5pp 阈值）与事件提示。**未核查事件日历前，不得输出“期权便宜/该买权/该卖权”结论**；候选仍限 `--min-days`/`--max-days`（默认3至45天）与 `--expiry-hint` 规则，规格未核验只能用于研究，详见 `references/options.md`。
6. 多周期共振、1H 入场、BOS/CHOCH/OB/FVG/扫单、新闻事件分析**未自动实现**。人工补充按 `references/technical.md` 和 `references/news.md` 核验并记录来源、时间、证据；无搜索/浏览器工具时明确“未核查”。API行情查询不等于新闻核查。
7. **token 纪律**：一条命令取全量数据，不重复跑；回复不逐字粘贴原始 JSON，把关键位转成表格；共享边界只在文末说一次；每个方案 2–4 句理由。不先输出长篇行情综述再给卡。

## 条件挂单卡模板

- 状态：等待 / 条件研究草案（非自动订单）
- 标的与产品：标的、交易所、线性/反向等；未确认则注明
- 数据时间：快照时间、最新已完成K线时间；现价与日线收盘的偏差大时必须说明
- 方向与触发：用户假设；明确价格/结构触发及有效期，缺失则等待
- 入场 / 止损触发 / 失效时间：条件值，不承诺成交
- 分批：批次价位（等权）、均价、共用失效价；未给本金只有价位没有批量
- 目标：毛1R/2R/3R（按均价）；负价格目标无效，费用后R另算
- 仓位：未提供本金或预算则“待确认”；否则仅列成本前线性估算与假设（覆盖全部批次）
- 风险：跳空、费用、流动性、强平及事件未核查项
- 期权适配：ATM IV vs 30日RV 差值事实 + 事件核查状态；默认“研究，不推荐执行”，或列研究候选

随后用2–4句说明证据、缺失核查和等待条件。

## 错误与验证

- `--json` 成功输出单个信封对象：`schema`、`generated_at_utc`、`symbols[]`（每标的一张卡）、`scan`（可选）、`shared_warnings[]`；紧凑单行JSON。失败输出单个error对象并以状态码2退出。不要混入进度文字。
- 单标的数据失败：该标的条目含 error 并计入 `partial_failures`，其余标的照常输出；全部标的失败才整份失败。期权接口失败保留行情研究并标unavailable；指定 `--expiry-hint` 无法核实则整份失败，不静默回退。
- 无效/非有限数、错向止损、过期/越界指定expiry、缺少已完成历史、数据过旧或有缺口：不出方案。
- 离线回归：`python -B -m unittest discover -s tests -v`。测试不调用网络、不访问账户。
