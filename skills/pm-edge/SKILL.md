# 预测市场研究

只读分析，不代下单。结论是条件计划，不是保证。

## 输出格式（这一节优先于其它一切）

**默认用表格。** 用户要的是"扫一眼就知道买什么"，不是研究报告。

先给结论表：

| 市场（城市/日期） | 方向 | 档位 | 挂单价 | 模型给的胜率 | 赔率 | 边际 | 最大亏损 | 一句话依据 |
|---|---|---|---|---|---|---|---|---|

表下一行合计风险，再给 3–5 行"为什么"，最后一小节"没选上的及原因"。

**写作要求：**

- 城市一律用中文名（纽约、伦敦、东京、巴黎、圣保罗、墨西哥城、奥斯汀……），括号里可以带机场代码。不要把 `LFPB`、`KAUS` 这种代码当城市名摆在表头。
- 理由用大白话，像跟朋友解释："模型说最高 61°F，市场却把 62-63 抬到 0.70，等于赌它一定偏热。" 不要写 `p_model=0.305 vs ask=0.16, diff=+14.5pp` 这种代码腔。
- 数字只留两种：买入价、胜率。中间过程（sigma、bias、members）不进表格，用户问再给。
- 胜率写百分比，不写 0.305。价格写 0.16 或 16¢，统一。

单个市场的深挖才用块状格式：

```
## 挂单：纽约最高温 10/24（KLGA）
方向：买 YES 60-61°F
限价：0.16（盘口 0.12/0.17）   数量：180 份 ≈ $28.8
风险：全损 = $28.8
失效：NWS 或 ECMWF 把最高推到 63°F 以上
```

## 三个必答问题

**1. 结算源是什么？** 一句话写出"当且仅当 ___ 时结算为 YES"，并给出结算页面、日期时区、精度、修订规则。写不清 → PASS。口径细节见 `references/weather.md`（温度）与 `references/crypto.md`（价格盘）。

**2. 是当天还是明天？** 当天有观测，可以做单调排除；明天只有预报，概率是模型近似。两者不能混：**不能用今天的观测去判明天的盘**。

**3. 费用与 NO 报价拿到了吗？** 费率未知就只报毛收益；NO 必须读真实 NO 订单簿。见 `references/mechanics.md`。

## 工作流

### 第 0 步：先结算昨天

```bash
python scripts/pm_weather.py --settle 2026-10-24
```

一张表出全部市场的实际值、获胜档、模型中心的偏差。**每天扫新机会前先跑这个**——校准是靠每天的结算喂出来的，不结算等于白亏学费。香港摘录滞后 1–2 天，隔天再补跑一次。

### 第 1 步：一次扫完，别分十几步

```bash
# 天气盘一站式（推荐）：自动取规则、站点、观测、三模式集合、真实盘口
python scripts/pm_weather.py --date 2026-10-25 --mode both --top 10 --min-edge 0.05

# 只想看高胜率（NO 侧）
python scripts/pm_weather.py --date 2026-10-25 --mode no --min-edge 0.05
```

`pm_weather.py` 已经内建了以前要手工做的全部口径：routine METAR（排除 SPECI 和美股 5 分钟 AUTO 记录）、当地日、四舍五入进档、香港天文台口径、三模式偏差修正、真实 YES/NO 订单簿 VWAP、NO 侧抗漂移过滤。

**速度**：观测/集合/前一天预报按时区分组批量拉取（Open-Meteo 多坐标一次请求、IEM 每 6 站一次），冷启动约 1.5–2 分钟全部 82 个事件，热缓存秒级。**不要为每个城市单独跑一次**，一次 `--date` 就够；也不要重复跑同一个日期，缓存会命中。

```bash
# 其它类别
python scripts/pm_scan.py --tag awards,movies,music,pop-culture --top 12
python scripts/pm_scan.py --platform kalshi --series KXHIGHNY,KXHIGHLAX --top 10
```

### 第 2 步：当天盘做单调排除

```bash
python scripts/pm_temp_brackets.py --limit 60 --top 12
```

只输出 `IMPOSSIBLE_ABOVE` / `IMPOSSIBLE_BELOW` / `STILL_POSSIBLE`。**当天结束前的极值仍可能改变，没有"锁定档"。** 买"赢的那一档"缺乏可证明边际；能证明的只有已死档位的 NO，而它们通常已经在 0.99 附近。

### 第 3 步：加密价格盘

```bash
python scripts/pm_barrier.py --spot 82000 --barrier 85000 \
  --deadline "2026-11-01T03:59:00+00:00" --iv 0.40 --mode touch --ask 0.61 --fee-rate 0.07
```

### 第 4 步：算净边际与单位风险

```bash
python scripts/pm_edge.py --p 0.55 --price 0.42 --fee-rate 0.02 --equity 1000 --risk-pct 1
```

### 第 5 步：记录与校准

```bash
python scripts/pm_calibration.py log --question "..." --p 0.55 --price 0.42
python scripts/pm_calibration.py resolve --id <id> --outcome yes
python scripts/pm_calibration.py score
```

## 两种打法，别混着讲

**便宜期权（YES side）**：模型说 30%，市场卖 5%。赢了赚十几倍，但十次错七八次。适合小钱（$10–20），必须接受"多数单子归零"。只做有独立证据的（官方预报/结构性的降雨/地形），不做纯模型偏差修正出来的。

**高胜率（NO side）**：模型说这一档只有 5–10% 会中，市场 NO 只卖 0.55。赢面 90%，但赔率低（0.8:1），一次踩雷要赢好几次才回来。**用户说"稳一点""高胜率"时默认给这一类。**

**NO 的抗漂移门槛（10-24 用真金白银换来的规则）**：边际够但"离三模式中心只有 1 档"的 NO 是陷阱——预报整体偏 1°C（最寻常的误差）就正好砸在你卖的档上。10-24 的华沙 6°、亚特兰大 70-71° 都是这么死的。所以 NO 只给**漂移后仍有 ≥5pp 边际**的档（脚本已内建，表里"抗漂移胜率"列）：±1.5°C 朝该档漂移后胜率跌破买入价的，默认过滤（`--risky` 可看）。远端 NO（离中心 ≥2 档）天然过这个门。

两者都要求：真实 NO/YES 订单簿能成交、2¢ 内**同侧**深度 ≥ 5 倍单量、三模式中心分歧 < 1.5 度。分歧大的（比如墨西哥城三模式 20–24°C）直接不给，那不是机会是噪音。

## 判据（可按证据偏离，但要写理由）

| 项 | 参考值 |
|---|---|
| 模型概率 vs 买入价 | ≥5pp 才进表；≥10pp 才算主力 |
| NO 抗漂移 | ±1.5°C 漂向该档后，胜率 − 买入价 ≥5pp，否则过滤 |
| 价差 | ≤3¢；>5¢ 基本放弃 |
| 深度 | **同侧** 2¢ 内 ≥5× 计划金额（YES 行不能用 NO 侧深度凑数） |
| 三模式中心分歧 | ≤1.5°C / ≤2.7°F，超了就 PASS |
| 降雨 | 目标日 >5mm 时，晴天的历史偏差不能套用，概率要打折 |
| 剩余时间 | ≤90 天；当日盘注意当地日结束时间 |
| 已下场复查 | 当地时间早晨用实时 METAR/当日模型核一遍持仓 NO 是否已被击穿；YES+NO 合计 <1 时可两侧锁定价差 |

## 没机会时逐级放宽

1. 放宽边际到 3pp、深度到 3×。
2. 放宽成交量到 $500，允许薄盘小仓。
3. 换方向：YES 没肉就找 NO。
4. 换类别：天气 → 文化 → 加密。
5. 仍然没有：说"今天不做"，给触发价和观察清单。不为有单而下单。

## 默认 PASS

- 结算规则含糊、来源打不开、平局/取消/缺失数据兜底不明。
- 你确定要买的一侧拿不到可成交价或费率。
- 唯一理由是"已经 95% 了"。
- 概率与价格差不到 2pp，且没有独立依据。
- 三模式中心差 2 度以上，却只有一个模型支持你的方向。
- 薄盘（2¢ 内深度 < 5× 单量）硬要报边际——VWAP 会把你吃掉。
- 想加仓挽回上一笔亏损。
