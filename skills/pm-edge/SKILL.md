# 预测市场研究

在现有 pm-edge 内完成通用事件研究和天气专用分析，不新建同类 skill。只读，不自动下单。

## 第零步：问用户偏好

每次扫描前用 AskUserQuestion 问交易风格，默认高胜率：

| 风格 | 含义 | 筛选侧重 |
|---|---|---|
| 高胜率（默认） | 愿意接受低赔率换更高命中概率 | p_stress ≥ 80%、压力测试通过、深度充足 |
| 高赔率 | 愿意承受更低命中率换单笔高回报 | 远档 YES 或低价 NO，净边际 > 10pp |
| 均衡 | 胜率和赔率都看 | 净边际 > 5pp 且 p_stress > 60% |

用户不回答就按高胜率走。问完后把风格写进表头，让用户一眼看到筛选逻辑。

## 先给用户能读懂的结论

默认中文表格，理由用大白话。天气每行必须含中文城市名、完整日期、最高温或最低温和档位；其他市场写对象、截止时刻及时区、YES 成立条件。

| 情绪 | 城市 | 方向 | 档位 | 入场价 | 挂单价 | 模型概率 | 边际 | 成交量 | 买盘YES |
|---|---|---|---|---|---|---|---|---|---|

- **入场价**：当前可成交价（YES ask 或 NO ask），立即成交的价格
- **挂单价**：被动限价（YES bid 或 NO bid），等回撤的价格。没有 bid 时写”—“
- **方向**：明确写”买YES”或”买NO”，不要只写档位
- **模型概率**：p_stress（压力测试下的概率），标注”未校准”
- **边际**：模型概率 − 入场价，正数才列候选
- **情绪**：🟢 强一致（模型+市场同向，边际>10pp）/ 🟡 观察（边际正但情绪中性）/ 🔴 分歧（模型与市场矛盾）
- **买盘YES**：bid 侧 YES 深度占比，反映市场资金方向

🟢 和 🟡 都放在主表里，🔴 只列前 3 个或省略。表后 1–2 句说明最强候选的依据和风险。

## 六步通用流程

1. **问偏好**：用 AskUserQuestion 问交易风格（高胜率/高赔率/均衡），默认高胜率。把风格写进输出表头。
2. **读规则**：核对平台/市场ID、对象、日期时区、YES/NO 边界、指定结算源、取整、平局/取消/修订/缺失数据处理。只读标题不够。无法核实的标”待规则核对”。
3. **取独立证据**：先记录可追溯的预测来源、发布时间和估计区间，再比较价格。天气看结算站预报；计数看指定追踪器当前累计和剩余时间；文化/体育/政治看基准率与事件证据。
4. **读真实盘口**：Polymarket 分别读取 YES 与 NO token；Kalshi 按官方二元互补买盘规则重建卖价并注明。检查两侧价差、计划数量的完整成交、费用和数据时点。
5. **读市场情绪**：按下表分析盘口结构，判断市场资金方向和信心强度。情绪与模型同向时加分，反向时降权或放弃。
6. **选方式 + 留证**：按下表提出条件计划。保存判断时点、来源、概率、报价、候选/不参与原因。跨市场先核对结算口径是否完全一致。只有当地日结束且指定来源已发布的结果才进入正式结算。

## 可选研究方式

| 方式 | 用什么判断 | 输出边界 |
|---|---|---|
| 事件价值 | 基准率、独立证据、概率区间与成本比较 | 区间下界仍覆盖成本时才谈稳健优势 |
| 高胜率方向 | YES 和 NO 都看，结合结算确定性和模型校准 | NO 本身不等于高胜率，单看贵价也不够 |
| 回撤接单 | 当前报价与更低被动限价，结合后续事件 | 低价提高条件赔率，不保证成交或原概率仍有效 |
| 盘口/情绪观察 | 买卖价差、买盘深度占比、卖盘供给和连续快照 | 可提示拥挤、流动性变化；单次快照不证明动量或方向胜率 |
| 事件催化 | 公布日程、计数速度、榜单/调查/赛程更新 | 指定触发和失效条件；事件后立即重估 |
| 配对价差/持仓对冲 | 相同二元事件的等份 YES+NO 成本 | 两侧 ask 足额、费用/兑换条件已核实后才谈条件净价差；非原子成交有单腿风险 |

没有一套概率模型适合所有类别。通用入口能发现/核对各种合约，不等于已为每类训练独立模型。

## 市场情绪分析（必做）

每个候选必须计算以下指标，写入表格：

| 指标 | 计算 | 含义 |
|---|---|---|
| **入场价** | YES ask（买YES）或 NO ask（买NO） | 立即成交的价格 |
| **挂单价** | YES bid（买YES时）或 NO bid（买NO时） | 被动限价，等回撤用 |
| **边际** | 模型概率 − 入场价 | 正数才有交易价值 |
| **买盘YES占比** | `yes_bid_depth / (yes_bid_depth + no_bid_depth)` | >60% 市场偏 YES，<40% 偏 NO |
| **成交量** | `vol`（美元） | >$1000 有真实博弈，<$200 可能是僵尸盘 |

**情绪标签判断**：
- 🟢 **强一致**：边际 > 10pp 且 买盘方向与模型一致（买YES 时 买盘YES > 60%，买NO 时 买盘NO > 60%）
- 🟡 **观察**：边际 > 0 但 买盘方向中性（40-60%）或 边际较薄（<10pp）
- 🔴 **分歧**：边际 > 0 但 买盘方向与模型矛盾，或 成交量 < $200

**输出要求**：
- 🟢 和 🟡 都放在主表，按边际降序
- 🔴 只列前 3 个或省略，避免信息过载
- 表后 1–2 句总结最强候选的依据和风险

## 脚本入口

从 skill 目录运行；参数以各脚本 `--help` 为准。一次批量扫描，避免为每个城市反复写临时脚本。

### 脚本速查

| 脚本 | 用途 | 常用参数 |
|---|---|---|
| `pm_weather.py` | 天气盘扫描+结算+校准 | `--date`, `--only`, `--mode`, `--settle`, `--bias`, `--json` |
| `pm_scan.py` | 通用市场扫描（Polymarket/Kalshi） | `--tag`, `--platform`, `--series`, `--books`, `--top` |
| `pm_edge.py` | 给定概率算净成本/边际/仓位 | `--help` 查看参数 |
| `pm_barrier.py` | 触碰类事件分析 | `--help` 查看参数 |
| `pm_calibration.py` | Brier 分数、与市场价比较 | `--help` 查看参数 |

### 常见用法

```bash
# 扫明天所有天气盘，输出前 8 个候选
python scripts/pm_weather.py --date 2026-10-30 --mode both --top 8

# 只扫特定城市（快）
python scripts/pm_weather.py --date 2026-10-30 --only 香港,东京,纽约 --mode no

# 输出 JSON（方便程序分析）
python scripts/pm_weather.py --date 2026-10-30 --json > output.json

# 结算历史日期
python scripts/pm_weather.py --settle 2026-10-28

# 查看模型校准（偏差、命中率）
python scripts/pm_weather.py --bias

# 扫 Polymarket 文化/娱乐类市场
python scripts/pm_scan.py --tag awards,movies,music,pop-culture --books 8 --top 8

# 扫 Kalshi 天气盘
python scripts/pm_scan.py --platform kalshi --series KXHIGHNY,KXHIGHLAX --top 8
```

费用参数只在查清市场当前规则后提供；用户指定假设费率只能标情景计算。不要按类别猜费率，更不能默认未知费用为零。

## 盘口占比怎么用

分别写“买盘 NO 占比”和“卖盘 NO 占比”，注明最优价附近的价格带及美元深度。前者是挂着买入 NO 的流动性，后者是愿意卖出 NO 的供给，均不等于交易人数、持仓比例或事件概率。报价本身含市场隐含倾向，但需要独立证据才能判断有无优势。

3× 计划金额的本侧 2¢ 深度可用作可调流动性缓冲，这是本工具的研究启发式，不是官方盈利定律。薄盘给容量上限/等价条件，不能把部分成交均价当全额成交价。

## 天气专用约束

- 每个合约重新核对站点、结算源、当地日和进档规则。香港天文台与 VHHH 机场不同；机场读数不可代填天文台结算。
- 集合成员比例是未校准估计。HKO 预报评分的容忍区间不等于统计标准差；网格预报残差也不等于官方预报残差。
- 中心落在所卖 NO 档内、普通漂移便能击穿的候选列观察；压力测试包含零漂移。距中心 ≥2 档也不能取消同样的压力门槛，不能为“救回某个推荐”调规则。
- 当天最高温只能继续升高、最低温只能继续降低；可以排除被突破的档，不能提前宣布剩下一档必胜。
- 旧缓存曾有批量站点映射污染。新缓存按版本隔离并核对坐标/请求身份；历史无来源、无预测时点或未结束当地日的记录不进入校准。
- `--risky` 仅用于查看被筛掉的诊断候选，不把它们转成正常推荐。

## 发布与验证

修改核心计算后补覆盖错误场景的永久测试。离线测试通过只证明实现，不证明真实胜率提升；实网取数成功只证明该次接口能用。不要把 6 条中心命中记录当作交易胜率。

只有用户授权上传时才 push。上传同步更新 Release 并核对其目标提交及 pm-edge.zip、trade.zip；已有 stock 时可同时附 stock.zip。打包排除缓存、账本、密钥和临时文件；保留用户 README 截图，不加日期流水账。
