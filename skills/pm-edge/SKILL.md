# 预测市场研究

在现有 pm-edge 内完成通用事件研究和天气专用分析，不新建同类 skill。只读，不自动下单。

## 先选入口

- 流动性好的体育、宏观数据、政治大事件 → 优先用 `pm-liquid`（盘口可执行性优先、默认挂单、跨平台比价）。
- 天气、逐日温度档位、推文计数、奖项票房等日更或慢变量 → 用本 skill。
- 用户只说“扫描”且没指定类别时，先问一句类别或先跑 `pm-liquid`，不要默认天气。

## 核心方法论：市场优先，独立证据解释偏离

- **报价是市场基线**：先看同一时点的 bid、ask、价差和可成交数量，了解市场定价。ask 是买入该侧的执行成本，不是真实概率；市场共识也不保证获胜。
- **独立证据解释偏离**：规则、指定来源、可追溯的事前预测与事件证据用于判断是否有理由偏离市场基线。不能仅因模型与市场一致就提高胜率，也不能因二者冲突就自动认定市场或模型正确。
- **流动性只管执行**：成交量、价差、深度影响报价可用性、容量和滑点；挂单占比不是方向信心或事件概率。薄盘不是提高模型权重的依据。
- **模型输出分清身份**：集合成员比例、平滑值和漂移压力测试都只是模型情景；`p_calibrated` 只是字段名，不构成证明；正态 CDF 与 σ 下限只改变分布假设。
- 不使用无来源命中率、概率映射或固定市场/模型 blend。没有同口径事前预测、已核实结果与样本外验证，就不声称概率已校准。

## 默认偏好与输出

首次使用且上下文没有偏好时，借鉴 grill-me：先用 AskUserQuestion 问一个选择题（高胜率〔推荐〕 / 均衡 / 高赔率），一次只问一题；只有答案会实质改变扫描范围时才继续追问。不进行冗长访谈。用户已明确偏好、明确要求直接扫描或无法交互时，默认按**高胜率**直接研究并在表头注明，不重复问；用户要求切换时再调整。已明确高胜率且接受合理限价的用户，无需在立即买入和挂单之间重复选择。高胜率不等于买贵价或买 NO，必须结合结算确定性、独立证据与不确定性判断。

“挂远一点”默认指**更低的买入限价**，不是离预测中心更远的温度档。低价改善条件赔率，不保证成交，也不自动提高胜率。

优先能挂单的深盘：价差、本侧 ask 20 份完整成交、费用可查；薄盘只作观察，不因价格低就提高模型权重。低价档（<10¢）不因便宜就买，高价档（>90¢）不追；低价只提高赔率，不证明胜率。

默认中文简明表格，理由用大白话；不设每行词数硬限制，必要细节放表后。天气行合并写"城市·日期·最高/最低·档位"；其他市场写"对象·截止时刻（时区）·YES条件"。

| 状态 | 对象·档位 | 方向 | 市场/天气 | 挂单/失效 | 胜率依据 |
|---|---|---|---|---|---|

- "市场/天气"列合并写：本侧ask（即时成本）·bid（挂单参考）·价差；天气另加预报中心与实测差。
- "挂单/失效"列合并写：入场参考价→可挂限价，一句失效条件。
- "胜率依据"列只写证据类型：如"集合情景70–80%"、"官方预报+残差"、"未能可靠估计"。不写完整句。
- 表后说明理由与缺口；候选行序综合市场倾向、条件价值、流动性、不确定性，不另设排序列。主表可列市场偏稳的条件方向，但须与独立证据支持的价值方向区分，普通参考不冒充已验证高胜率。
- 方向明确买YES/NO；用本侧真实ask作执行成本，非中价/bid；缺失报价写"未知"。
- 概率只写有依据的范围；模型只给"集合情景X–Y%"，并同时列市场价；无可支持数值写"未能可靠估计"，不倒用ask编造。市场报价是情绪基线，模型情景不充当真实胜率。
- 费用口径已核实才写净边际，否则标毛值；单位期望`p*v-c`，见`references/risk.md`。
- 状态三档：**当前可考虑 / 等待限价条件 / 不参与**。纯观察单列，不冒充推荐；不足3候选报告已查范围合格数。默认输出3–6个候选，用户说"多给几个/参考"时可列更多。

### 有成交可能的挂单，而不是许愿价

先核对本侧 bid/ask、tick、价差和容量，再给近端挂单区间；高胜率与等待成交不矛盾。极高买价的获胜回报薄，按用户偏好降低优先级；低至1¢不等于利润薄，只是低价也不证明胜率或价值。不设统一价格硬阈值，不把0.60–0.90当作盈利定律。价格依据可来自当前买盘、价差内可挂价格，或确实取得的近期成交/历史盘口，说明用了哪一项。

用户说"挂远/更远"时，不机械按bid减2–5¢。只有真实取得的成交历史或连续盘口支持时才给远端价，并写明历史时段与依据；无历史则写"无触达依据"，不把假设折价说成历史波动。更远的低价仅在上述证据支持可能触及时作为次级条件，不能机械打折或挂到几乎无依据会到的位置。没有历史/连续快照时，明确"成交概率未知"，不编造触达率；不为估计触达率无限取数。价差窄且当前成本合理时，可直接列当前可考虑，不强制折价。限价同时受可解释的条件价值上限约束，买一价本身不证明便宜。价格到达后重估证据和费用，失效则撤销；没有账户资金与风险预算不生成实际仓位。

## 自动扩批发现

首批扫描3–4个候选后，**不足3个合格即自动扩第二批不同城市**，无需用户再问，最多两批。第三批仅用户明确说"再看看/还有没有/全扫"时才启动。触发条件：不足3候选，或用户说"再看看/还有没有"。达到两批、接口失败或继续扫描收益低时，报告合格数量与停止原因。未指定城市按当前活跃度、目标日及可核实来源选少量覆盖，不固定历史名单。用户要求"重新扫/忽略前面"则新一轮独立研究，本轮查过的城市仅作参考仍需重核报价。同轮复用新鲜且口径匹配的缓存，关键更新才刷新；优先精简结构化字段，不回显全量JSON。

## 六步通用流程

1. **定偏好与范围**：默认高胜率，尊重用户已有要求，不重复询问。
2. **读规则**：核对平台/市场 ID、对象、日期时区、YES/NO 边界、指定结算源、取整、平局/取消/修订/缺失数据处理。只读标题不够；无法核实标“待规则核对”。
3. **读市场基线**：报价前将 bids 按价格降序、asks 按价格升序排序，禁止用未排序数组首项当最优价；20份等执行量须跨档计算VWAP并确认足额。Gamma 的 outcomePrices/clobTokenIds 若为JSON字符串先解析；API响应必须匹配所请求ID、标题与目标日，不支持筛选而返回其他市场时拒绝使用。候选shortlist不是完整市场，缺席不能称合约移除。同一事件同时评价 YES/NO；多档事件查看完整档位的市场分布与独立预测分布（未能取得则注明），比较各侧当前费用后条件价值，不只看扫描器高模型边际或 NO 输出。Polymarket 分别读取 YES/NO token；Kalshi 按官方二元互补买盘规则重建卖价并注明。检查价差、完整成交、费用和时间戳；市场高概率侧也纳入核对，不把其报价当真实胜率。
4. **取独立证据**：保留可追溯来源、发布时间与预测时点，解释相对市场的偏离。天气核对结算站；计数核对追踪器累计与剩余时间；其他类别核对基准率与事件证据，不能从 ask 倒造独立概率。
5. **核对执行与风险**：盘口仅说明供需和容量，不证明方向信心。结合不确定性、相关性与条件成本判断，不因深度大或模型一致直接宣布高胜率。
6. **选方式并留证**：给条件计划、失效条件和不参与原因；跨市场先核对结算口径。有过跟踪方向时，列旧时点及依据、新证据和判断变化；只有实质新证据支持才更新方向，排名变化不是反向信号。旧报价/挂单参考注明到期或失效，不能沿用旧价当现价；证据不足可暂停判断，不机械维持或翻向。保存事前证据和报价，只有当地日结束且指定来源已发布并核实的结果才能进入可信统计。

## 可选研究方式

| 方式 | 判断与边界 |
|---|---|
| 事件价值 | 独立证据与概率区间对比成本；模型情景只能作条件计算 |
| 高胜率方向 | YES/NO 都看，贵价或 NO 标签本身不是高胜率证明 |
| 回撤接单 | 比较当前 ask 与更低限价；成交时重新核对证据，防止逆向选择 |
| 盘口观察 | 价差、深度和连续快照提示供需变化，不证明胜率或动量 |
| 事件催化 | 明确公布日程、触发与失效条件，事件后重估 |
| 配对价差 | 等份 YES+NO、两侧 ask 足额、费用及兑换核实；非原子成交有单腿风险 |

没有一套概率模型适合所有类别。能发现和核对合约，不等于已为每类验证概率模型。

## 脚本入口

从 skill 目录运行，参数以脚本 `--help` 为准。天气扫描一律用 `pm_weather.py`（含 `--settle` / `--risky`），不要手工拼流程或为每个城市创建临时脚本。

| 脚本 | 用途 | 常用参数 |
|---|---|---|
| `pm_weather.py` | 天气扫描、结算核对与诊断 | `--date`, `--only`, `--mode`, `--settle`, `--bias`, `--risky`, `--json` |
| `pm_scan.py` | 通用市场扫描 | `--tag`, `--platform`, `--series`, `--books`, `--top` |
| `pm_edge.py` | 给定概率的条件成本、边际与仓位计算 | `--help` |
| `pm_barrier.py` | 触碰类事件分析 | `--help` |
| `pm_calibration.py` | 可信样本的 Brier 与市场基线比较 | `--help` |

示例（日期换成目标日，城市/系列按当轮发现范围选择；不是默认固定城市）：

```bash
# CITY_FILTER 为当轮选出的少量城市
python scripts/pm_weather.py --date 2026-11-02 --only "$CITY_FILTER" --mode both --top 5
python scripts/pm_weather.py --settle 2026-10-28
python scripts/pm_weather.py --bias
python scripts/pm_scan.py --tag awards,movies,music,pop-culture --books 3 --top 5
python scripts/pm_scan.py --platform kalshi --series "$SERIES_FILTER" --top 5
```

费用逐市场核查，不按类别猜费率，不把未知费用当零。用户指定费率只能标假设情景。

## 天气专用约束

- 每个合约重新核对站点、指定源、当地日、单位和进档规则；香港天文台与 VHHH 机场不同，不可互相代填。
- 集合、正态平滑、网格残差代理与漂移结果都只是模型情景，不是实测概率。官方评分容忍区间不是统计标准差，网格残差不是官方预报误差。
- 天气发现范围兼顾最高温、最低温及市场高概率侧；未覆盖部分列明原因。扫描器候选不是市场全集，有限扫描不能推出“市场无机会”或泛称“无高胜率”。跨轮方向变化须明确依据；同一城市在相邻轮次中若从YES改NO或反之，须说明新证据而非仅报告"模型候选变了"。
- 压力测试衡量假设敏感性，不是实际概率，也不是普遍必要或充分的盈利条件。所有 NO 使用同样的压力情景，包含零漂移；远离中心也不能豁免，不为救回某个候选调规则。脚本既有筛选参数是研究启发式，不是胜率证明。
- 当天最高温只能继续升高、最低温只能继续降低；可排除已突破档位，不能提前宣布剩下一档必胜。
- 结算 `pending_source_verification` 不进入可信统计；当地日结束或代理数据到齐不等于指定源已核实。
- 事前预测快照采用追加记录，保留时点与来源，但追加不是防篡改保障。没有有效事前记录不能事后补造预测。
- `--risky` 只展示诊断项；正式脚本硬筛未通过须如实标注，不悄悄绕过或为凑推荐改门槛。若另做独立研究，须提供额外证据并注明独立研究身份与原筛选失败，不能冒充脚本合格项。

## 发布与验证

核心计算变更应有永久测试；离线测试通过只证明实现，不证明真实胜率提升；接口成功只说明该次可用。中心命中率不是交易胜率。

仅用户授权上传时才 push。上传时同步更新 Release 并核对目标提交及 pm-edge.zip、trade.zip；已有 stock 时可附 stock.zip。打包排除缓存、账本、密钥和临时文件，保留用户 README 截图，不加日期流水账。
