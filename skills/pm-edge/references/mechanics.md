# 平台机制、费用与订单簿

## 一、Polymarket

- 市场元数据走 Gamma（`/events`、`/markets`），订单簿走 CLOB（`/book?token_id=`）。
- 取市场务必用 **events 端点按 tag 拉**，再展平 markets；用 `/markets` 全站切片会漏掉整个类别。
- `bestBid` / `bestAsk` 一般指 YES 一侧。**NO 的买单必须读 NO token 自己的订单簿**，不要用 `1 − YES bid` 当可成交价。
- `outcomePrices` 是中价参考，**不是可成交价**；拿它算边际等于自欺。
- `negRisk`：多档互斥事件。多档价格之和接近 1 是正常的，不代表有套利；各档能否成交、能否转换都是问题。
- 费率看市场的 `feeSchedule.rate`；`feesEnabled` 为真但拿不到费率时，费率就是**未知**，不能填 0 或填一个猜测值。
- 最小单、tick size、地区限制都要在看板上确认。

## 二、Kalshi

- 公开市场数据可匿名读；下单需要 API key 与签名。
- 注意字段版本差异：新版返回 `yes_bid_dollars` 这类字符串，老代码读 `yes_bid` 会得到空值，看起来像"没有行情"。
- 系列代码（如 `KXHIGHNY`）才能稳定拉到日高温盘；全站切片会漏。
- 费率以官方费率页为准，不同系列可能不同；不知道就不算净成本。
- 结算口径与 Polymarket 不同（天气盘用 The Weather Company），不能混用。

## 三、费用与可成交性

净成本 = 可成交价 + 费用。费用口径：`rate × price × (1 − price)`（按平台说明为准）。

三个必须遵守的点：

1. 费率未知 → 只报毛收益，不报净边际。
2. 滑点用订单簿 VWAP 走单，不用最优一档。金额越大，VWAP 越差。
3. 深度按"计划金额的倍数"检查。2¢ 内没有 3 倍于计划金额的深度，就缩小或放弃。

## 四、限价、成交与撤单

- 限价单不保证成交，也不保证是 maker；未成交就是不成交。
- 部分成交会让实际仓位小于计划，费用按实际成交计。
- 市场临近日程或数据发布时，挂单可能被扫或长时间不成交，需要主动撤单。
- 「止损」在预测市场里通常只是反向限价单，**不保证成交价**，跳空时可能滑很远。

## 五、结算与争议

- 结算以规则指定的来源为准，不是以新闻、也不是以别的交易所为准。
- 允许更正的条款（例如"7 天内可修订"）意味着结果可能在结算后变化。
- 无数据兜底条款（例如"缺失则按最低档结算"）是真实风险，必须读。
- 平局、取消、延期如何处理，写不清就是 PASS 的理由。

## 六、常见错误

- 拿中价或最新成交价当可成交价。
- 用 YES 盘口倒推 NO 价格。
- 在费率未知时算出漂亮的净边际。
- 把多档之和偏离 1 当成套利（多数时候是费用、深度和不可成交性造成的）。
- 以为限价单一定免手续费、一定成交。
