# pm-weather：天气预测市场研究

只读，不自动下单。优先最高温、最低温和逐日温度档位；降水、风速等其他天气事件仅按需研究，先核实数据与结算口径，不把温度模型或脚本能力泛化成已支持承诺。

非天气事件不属本 skill。体育、宏观、政治、加密价格等流动性事件合约转 `pm-liquid`；推文、奖项、票房等不再由本 skill 承接，也不声称 `pm-liquid` 已有这些类别的专用概率模型。保留的通用脚本与历史参考不改变此边界。

## 先说人话（默认表达）

用户要的是“买什么、挂多少、什么时候撤”，不是研究过程。默认按这个顺序回答：

1. **第一段先给结论**：今天有没有值得挂的单；没有就直说“没有合格单”，并说清是市场太贵、证据不够还是流动性太薄。
2. **默认只给一张挂单表**：买什么｜挂单价｜20 份成本｜什么情况撤。方向和档位写在“买什么”里，例如“上海 11-07 最高 20°C · 买 NO”。
3. **盘口、预报、模型、费用放表后 3–5 行**，不塞进每一行；用户追问再展开完整档位、容量和计算。
4. **解释“市场为什么这么定价”时，用“谁把中心拉到哪”**：官方预报多少、哪个模型偏暖或偏冷、市场在跟谁。不要只报一堆百分比。
5. **术语第一次出现就翻译**（见下方“术语翻译”）：YES/NO、bid/ask、价差、VWAP、p_calibrated、Kalshi、结算站，不要直接丢英文。
6. **不写“胜率依据”这种生硬列名**：写“把握”或“一句话依据”，并注明情景不是校准胜率。
7. **用户没问的不主动展开**：σ、压力测试、费用公式和完整档位明细留到追问或“完整核对版”；但多档事件仍要先核对完整档位，默认只报用到和相邻档位，不能因为没展示就漏看。
8. **结论必须能执行**：给具体挂单价、份数和撤销条件；只写“关注”“可考虑”不算完成。

## 偏好与研究预算

首次使用且上下文没有偏好时，用 AskUserQuestion 问一个选择题：**稳健有赚头（推荐） / 均衡 / 高赔率**，一次只问一题；只有答案会实质改变范围时才追问。已有偏好不重复问；明确要求直接扫描或无法交互时，默认稳健有赚头并注明。它指证据较稳、条件回报仍值得研究，不是买贵价、买 NO 或保证赚钱。接受合理限价的用户无需反复选择立即买入或挂单。

未指定城市时，按当轮活跃市场、目标当地日和可核实来源选择少量覆盖，不固定历史名单。首批深查约 3–4 个候选，不足 3 个合格时自动扩第二批不同城市，默认最多两批；用户要求更多、再看看或全扫时继续按预算扩展。**3–6 是默认展示量，不是候选上限或凑数目标**。报告实际范围、合格数、缺失与停止原因；未覆盖不等于市场无机会。

同轮复用新鲜且口径匹配的缓存，关键时点变化再刷新；只回显必要结构化字段，不倾倒全量 JSON。重新扫描须重核报价，旧城市名单仅作参考。

## 判断原则

- **市场是基线，不是真实概率**：先看同一时点 bid、ask、价差和容量；本侧 ask 是买入成本，不能从 ask 倒造独立胜率。
- **独立证据解释偏离**：指定来源、可追溯的事前预报与观测解释相对市场的判断。模型与市场一致不自动提高胜率，冲突也不证明谁正确；不用固定市场/模型 blend。
- **模型如实标身份**：集合比例、正态平滑、网格残差代理、漂移压力测试都只是情景；`p_calibrated` 只是字段名，σ 下限不构成校准。没有同口径事前预测、核实结果与样本外验证，不声称已校准。
- **流动性只管执行**：深度、成交量和挂单占比不代表方向信心或事件概率。薄盘不提高模型权重，低价不证明价值，高价不证明稳胜。

## 六步天气流程

1. **定时间与范围**：先核实当前实际时间、城市时区和目标当地日，把“今天/明天”落实为明确日期；不沿用示例日期。区分观测时间、预报发布时间/有效期、市场关盘时间和结算发布时间。默认兼顾最高温、最低温与市场高概率侧，未覆盖部分列原因。
2. **读完整规则**：核对平台、事件/市场 ID、YES/NO token、标题、城市、最高/最低温、当地日、单位、边界取整、指定结算站与来源，以及修订/缺测/取消处理。香港天文台与 VHHH 机场不同，不可代填。只读标题不够，无法核实标“待规则核对”，不当作可参与项。
3. **读完整盘口与档位**：获取候选所需 YES/NO 完整订单簿，不把顶层报价或 shortlist 当完整 book/市场。bids 降序、asks 升序后取最优价，20 份等参考执行量跨档计算 VWAP 并确认足额，部分成交均价不冒充整笔价格。Gamma 的 outcomePrices/clobTokenIds 若为 JSON 字符串先解析；响应须匹配所请求 ID、token 归属、标题与目标日，筛选失效返回其他市场时拒用。Polymarket 分别读 YES/NO token；Kalshi 按官方二元互补买盘规则重建卖价并注明。多档事件展示完整档位的市场分布及独立预测分布，取得不足明确缺口；同时比较各侧成本与条件价值，不只追扫描器高边际或 NO 输出。shortlist 缺席不等于合约移除。
4. **取天气独立证据**：保留来源、发布与预测时点，核对站点、预报中心、当前实测和预测剩余时段。当日最高温只能继续升高、最低温只能继续降低；已突破可排除，不提前宣布剩下一档必胜。官方评分容忍区间不是统计 σ，网格残差不是官方预报误差。
5. **核对执行与风险**：逐市场核实 tick、价差、完整容量、费用与报价时间；未知费用不按零算，只标毛值。结合预报不确定性、同城/同日相关性和条件成本，不因模型一致或盘口深直接宣布高胜率。没有本金与风险预算不给实际仓位。
6. **给条件计划并留证**：说明参与方式、失效条件与不参与原因。跟踪方向变化时列旧时点及依据、新证据与变化；排名变化不是反向信号，证据不足可暂停。旧价标到期或失效。事前快照追加保存时点和来源，但追加不是防篡改；没有有效记录不能事后补造预测。仅当地日结束且指定来源已发布并核实的结果进入可信统计，`pending_source_verification` 不进入。

## 温度筛选与压力测试

- 多档事件必须先核对完整档位分布（默认只展示用到与相邻档位，用户追问再展开全表），预筛（决定拉哪些盘口）与候选表使用同一口径（中心情景 `p_calibrated`），不能用悲观漂移下界 `p_min` 预筛，否则紧邻预报中心的档位（如中心 14.9°C 时的 15°C 档）会在取盘口前被静默丢弃。缺席档位不等于无边际。
- 压力测试只衡量假设敏感性，不是实际概率或普遍必要/充分盈利条件。所有 NO 使用同样的压力情景，包含零漂移，远离中心也不豁免，不为救回候选调规则。
- `--risky` 只展示诊断项；硬筛未通过须如实标注，不悄悄绕过或为凑推荐改门槛。另做独立研究须提供额外证据，并标明独立研究身份和原筛选失败，不能冒充脚本合格项。

## 输出与条件限价

默认中文，先结论后表格，理由用大白话。行序综合证据稳健性、条件回报、流动性与不确定性，**不另设排序列**；市场偏稳的条件方向与独立证据支持的价值方向分清，普通参考不冒充已验证高胜率。

### 默认：一张挂单表

先给 1–3 句结论（有单/没单、偏哪边、为什么），再给这张表，四列就够：

| 买什么 | 挂单价 | 20 份成本 | 什么情况撤 |
|---|---|---|---|
| 城市·日期·最高/最低·档位·买 YES/NO | 具体限价；注明“可吃”还是“只挂” | 约 $X（容量不足写实际份数） | 一句可核对、可执行的失效条件 |

表头或表下一行注明报价时间（UTC）。盘口、预报中心、模型分歧、费用放表后 3–5 行备注，不塞进每一行；用户追问再展开。多档事件仍先核对完整档位，默认只列用到与相邻档位，用户追问再展开全表。

### 完整核对版（用户要细节或需要留证时）

| 状态 | 城市·日期·最高/最低·档位 | 方向 | 市场/天气 | 挂单/失效 | 把握/依据 |
|---|---|---|---|---|---|

- 状态：**当前可考虑 / 等待限价条件 / 不参与**；纯观察单列，不凑推荐。方向明确买 YES/NO。
- “市场/天气”：本侧 ask（即时成本）·bid（挂单参考）·价差·容量，附预报中心与实测；表头注明实际报价时间。报价缺失写未知。
- “挂单/失效”：入场参考→可挂限价，一句失效条件。“把握/依据”写证据类型及可支持的范围，如“四源都在 19°C 以下，情景 75–85%”；无可靠数值写“未能可靠估计”。模型情景与市场价并列，不充当真实胜率。
- 费用已核实才写净边际，否则标毛值；单位期望 `p*v-c` 仅在 p 的身份与依据明确时作条件计算，见 `references/risk.md`。

### 怎么解释“市场为什么这么定价”

用户问“为什么市场押这一档”时，用“谁把中心拉到哪”回答，不超过三句：

1. 市场中心：各档中价按概率加权，落在几度；
2. 官方中心：合约指定气象机构（CMA/NWS/JMA/HKO 等）报几度；
3. 模型中心：哪个模式偏暖、哪个偏冷，把中心拉到了哪。

例：“6 和 7 现在并列，市场中心约 6.8°C；CMA 官方 5°C、ICON 4.9°C，但 GFS 9.3°C 把中心拉高了。所以我买的是被压低的 5+6，不是追 7。”不要把“市场给 33%”当结论；要说明这个 33% 是谁的预报撑起来的。

先用真实 bid/ask、tick、价差与容量给有依据的近端限价；价差窄且成本合理可列当前可考虑，不强制折价。不设统一价格硬阈值，不把 0.60–0.90 当盈利定律；极高买价回报薄需权衡，1¢ 也不等于利润薄或值得买。

“挂远一点”指更低的买入限价，不是离预报中心更远的温度档。远端价仅在真实取得的成交历史/连续盘口支持时给出，注明时段和依据；无历史写“无触达依据，成交概率未知”，不机械减 2–5¢，不编造触达率或为此无限取数。限价受可解释的条件价值上限约束，bid 本身不证明便宜。未成交就是未成交，不保证 maker 费率；价格到达时重估证据与费用，失效则撤销。

## 术语翻译（第一次出现就用中文解释）

| 词 | 大白话 |
|---|---|
| YES / NO | 买“会发生” / “不会发生”；每份到期结算 $1 |
| bid / ask | 盘口最高买价 / 最低卖价；ask 是你现在买进的成本，bid 是你现在能卖出的价 |
| 价差 | ask − bid；越窄越容易按合理价成交 |
| VWAP | 按计划份数吃掉多层挂单后的平均成交价，不是第一档价格 |
| 20 份成本 | 买 20 份实际要付的钱；容量不足 20 份要说实际能买多少 |
| p_calibrated | 脚本按模型中心算的情景概率；名字叫 calibrated，但没有样本外校准，不是真实胜率 |
| 结算站 | 最终按哪个机场/气象站的 METAR 读数结算，例如上海 ZSPD、北京 ZBAA、纽约 KLGA |
| Kalshi | 美国 CFTC 监管的预测市场交易所，美元计价、每份 $1；和 Polymarket 是两家不同平台 |
| Polymarket | 加密 USDC 计价的预测市场，全球用户；天气盘多在这里 |

## 脚本与运行数据

天气扫描一律用 `scripts/pm_weather.py`（含 `--settle` / `--risky`），不手工拼流程、不为每个城市创建临时脚本。从 skill 目录运行，参数以 `--help` 为准。日期换成已核实的目标当地日，城市按当轮发现范围选择：

```bash
python scripts/pm_weather.py --date YYYY-MM-DD --only "$CITY_FILTER" --mode both --top 10
python scripts/pm_weather.py --settle YYYY-MM-DD  # 仅已结束且指定源已发布的当地日
python scripts/pm_weather.py --bias
```

`pm_edge.py` 可作给定概率的条件算术，`pm_calibration.py` 用于可信样本验证；保留 `pm_scan.py`、`pm_barrier.py` 等现有脚本，不将其存在解释为本 skill 继续承接非天气研究。

默认缓存仅在当前 Python 进程内存中去重，进程退出即消失；默认 import / --help / 扫描 / --json / --settle 均不写业务文件，也不读取旧磁盘缓存充当新数据。用 `--cache-mode disk` 或 `PM_WEATHER_CACHE_MODE=disk` 显式开启磁盘缓存；`off` 禁用缓存复用。磁盘模式保留各请求 TTL，并受有效期上限168小时、容量256MB保护；`PM_WEATHER_CACHE_TTL_HOURS`、`PM_WEATHER_CACHE_MAX_MB` 可调整，零禁用留存。

预测快照、规则正文、HKO预报历史及待核验结算历史默认均不保存，仅当次命令加 `--save-records` 才保存；缓存 disk 不会顺带启用历史。需要留证时在扫描和结算命令分别显式加该参数；规则正文按哈希去重。`--bias` 只读已有历史，无数据如实报告，不从旧缓存重建预测，也不把 pending 当 verified。

仅显式写盘时才创建外置目录：Windows 默认 `%LOCALAPPDATA%/trading-skills/pm-weather/cache` 与 `.../data`（macOS/Linux 使用系统用户缓存/数据目录）；可用绝对路径 `PM_WEATHER_CACHE_DIR`、`PM_WEATHER_DATA_DIR` 覆盖。历史不随缓存淘汰，不迁移或删除既有缓存/用户记录，不读取安装目录旧缓存。离线回归使用 `python -B -m pytest -p no:cacheprovider -W error tests`，避免生成字节码和 pytest 缓存；接口与真实市场验证另计。

## 每次任务收尾

完成或中断都核对本轮创建的文件、子进程、服务器与浏览器标签页。只清理可确认属于本轮的一次性下载、探针和测试缓存；仅停止本轮启动且不再需要的程序/任务，关闭本轮专用标签页，不关闭用户原有程序或其他任务。默认不留业务数据；用户显式要求的记录与正式产物保留，所有 `.mimosa/` 不动。不确定归属先保留说明；失败/取消也执行收尾，报告删除、保留、归档及仍运行项。命令优先用 `python -B`，避免字节码积累。

## 错误处理

- 网络错误时脚本会立即停止并报告失败的数据源（Polymarket/Kalshi/天气 API）；所有数据源均失败时退出码为 2，不生成报告；天气部分失败也以退出码 2 和 stderr 警告报告。保留通用扫描器的部分失败退出码 0 行为说明，不将其作为天气成功标志。
- Agent 遇到错误立即告知缺失，不把不完整结果当完整扫描；时间戳用实际扫描完成时间（UTC），不估计。
- prewarm 失败在 stderr 明确标注，不计入候选；单次取数超时为 40s。全城扫描在 IEM 不稳时仍可能超预算，不无限等待；改用 `--only "城市1,城市2"` 缩小范围，或报告观测源不稳、未在预算内完成，不静默生成残缺结果。
