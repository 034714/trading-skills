# pm-weather：天气预测市场研究

## 调用门槛

仅在用户明确选中 `pm-weather` 后执行本流程；“继续/再看看”只延续此前已明确选中的本技能任务，不凭话题相似猜测。编辑、审查本技能文件不等于授权运行市场研究。跨领域只说明边界并请用户明确选择对应技能，不自动加载、读取或运行其他技能；本技能列出的静态参考可按需阅读，但不启动其所属技能工作流。

只读，不自动下单。优先最高温、最低温和逐日温度档位；降水、风速等其他天气事件仅按需研究，先核实数据与结算口径，不把温度模型或脚本能力泛化成已支持承诺。

非天气事件不属本 skill。体育、宏观、政治、加密价格等流动性事件合约可建议用户明确选择 `pm-liquid`，不自动转入；推文、奖项、票房等不再由本 skill 承接，也不声称 `pm-liquid` 已有这些类别的专用概率模型。保留的通用脚本与历史参考不改变此边界。

## 先说人话（默认表达）

用户要的是”买什么、多少钱进、赢了赚多少”，不是研究过程。默认按这个顺序回答：

1. **第一段先给结论**：有没有值得做的单；没有就直说，一句话说清原因。
2. **默认只给一张三列表**：买什么（带风险色标）｜买入价｜赢了赚多少。YES 和 NO 都要覆盖，不只给 NO。方向写在”买什么”里，例如”🟢 巴黎 11-17 最高不是 18°C · NO”。
3. **风险色标**：🟢 模型与市场方向一致（差 <1°C）；🟡 中度分歧（1–1.5°C）或流动性偏薄；🔴 显著分歧（≥1.5°C）或证据不足。色标放第一栏开头，不另设风险列。
4. **赢了赚多少**：直接写”赚 X¢ / +Y%”，一眼看出投入回报。不写公式、不写”毛收益”术语、不每次重复”费用未知/tick 未核”。这些内部核验细节只在用户追问时展开。
5. **表后最多 2–3 行**：报价时间、一句统一撤销条件（如”指定站已报出该温度即撤”）、事件链接。模型中心、成交量、深度、完整档位、σ、压力测试等全部按需展开，不默认塞进表或备注。
6. **证据足才给具体价**：不足就写等待/不参与和原因，不编价格。
7. **台账是可选工具**：`--log-pick`/`--review` 仅在用户主动要求记录或复盘时使用，不主动推荐、不在默认输出中提及。

## 偏好与研究预算

首次使用且上下文没有偏好时，用 AskUserQuestion 问一个选择题：**稳健有赚头（推荐） / 均衡 / 高赔率**，一次只问一题；只有答案会实质改变范围时才追问。已有偏好不重复问；明确要求直接扫描或无法交互时，默认稳健有赚头并注明。它指证据较稳、条件回报仍值得研究，不是买贵价、买 NO 或保证赚钱。接受合理限价的用户无需反复选择立即买入或挂单。

未指定城市时，按当轮活跃市场、目标当地日和可核实来源选择少量覆盖，不固定历史名单。首批深查约 3–4 个候选，不足 3 个合格时自动扩第二批不同城市，默认最多两批；用户要求更多、再看看或全扫时继续按预算扩展。**3–6 是默认展示量，不是候选上限或凑数目标**。报告实际范围、合格数、缺失与停止原因；未覆盖不等于市场无机会。

同轮复用新鲜且口径匹配的缓存，关键时点变化再刷新；只回显必要结构化字段，不倾倒全量 JSON。重新扫描须重核报价，旧城市名单仅作参考。

## 判断原则

- **市场是基线，不是真实概率**：先看同一时点 bid、ask、价差和容量；本侧 ask 是买入成本，不能从 ask 倒造独立胜率。
- **独立证据解释偏离**：指定来源、可追溯的事前预报与观测解释相对市场的判断。模型与市场一致不自动提高胜率，冲突也不证明谁正确；不用固定市场/模型 blend。
- **模型如实标身份**：集合比例、正态平滑、网格残差代理、漂移压力测试都只是情景；`p_calibrated` 只是字段名，σ 下限不构成校准。没有同口径事前预测、核实结果与样本外验证，不声称已校准。
- **流动性只管执行**：深度、成交量和挂单占比不代表方向信心或事件概率。薄盘不提高模型权重，低价不证明价值，高价不证明稳胜。成交量只用来判断“20 份等计划量能不能成交”，不用来排序胜率。
- **市场优先、模型参考**：完整档位分布、众数档和可解释中心先作基线，官方预报与模型检验偏离，不以单边模型覆盖市场。中价只是带标签的价格代理，不叫真实概率；加权中心须说明档位代表值、归一化与尾档处理，缺项不伪精确。不从无可复核事前样本的小样本命中率推出交易规则，不固定禁止买邻档/卖最贵档，也不强制 55¢ 或模型差 0.5°C 门槛。

## 六步天气流程

1. **定时间与范围**：先核实当前实际时间、城市时区和目标当地日，把“今天/明天”落实为明确日期；不沿用示例日期。区分观测时间、预报发布时间/有效期、市场关盘时间和结算发布时间。默认兼顾最高温、最低温与市场高概率侧，未覆盖部分列原因。
2. **读完整规则**：核对平台、事件/市场 ID、YES/NO token、标题、城市、最高/最低温、当地日、单位、边界取整、指定结算站与来源，以及修订/缺测/取消处理。香港天文台与 VHHH 机场不同，不可代填。只读标题不够，无法核实标“待规则核对”，不当作可参与项。
3. **读完整盘口与档位**：获取候选所需 YES/NO 完整订单簿，不把顶层报价或 shortlist 当完整 book/市场。bids 降序、asks 升序后取最优价，20 份等参考执行量跨档计算 VWAP 并确认足额，部分成交均价不冒充整笔价格。Gamma 的 outcomePrices/clobTokenIds 若为 JSON 字符串先解析；响应须匹配所请求 ID、token 归属、标题与目标日，筛选失效返回其他市场时拒用。Polymarket 分别读 YES/NO token；Kalshi 按官方二元互补买盘规则重建卖价并注明。多档事件展示完整档位的市场分布及独立预测分布，取得不足明确缺口；同时比较各侧成本与条件价值，不只追扫描器高边际或 NO 输出。shortlist 缺席不等于合约移除。
4. **取天气独立证据**：保留来源、发布与预测时点，核对站点、预报中心、当前实测和预测剩余时段。当日最高温只能继续升高、最低温只能继续降低；已突破可排除，不提前宣布剩下一档必胜。官方评分容忍区间不是统计 σ，网格残差不是官方预报误差。
5. **核对执行与风险**：逐市场核实 tick、价差、完整容量、费用与报价时间；未知费用不按零算，只标毛值。结合预报不确定性、同城/同日相关性和条件成本，不因模型一致或盘口深直接宣布高胜率。没有本金与风险预算不给实际仓位。
6. **给条件计划并留证**：说明参与方式、失效条件与不参与原因。跟踪方向变化时列旧时点及依据、新证据与变化；排名变化不是反向信号，证据不足可暂停。旧价标到期或失效。事前快照追加保存时点和来源，但追加不是防篡改；没有有效记录不能事后补造预测。仅当地日结束且指定来源已发布并核实的结果进入可信统计，`pending_source_verification` 不进入。**默认不写记录；仅用户明确授权记录才 `--log-pick`，保存预测/规则另需明确授权并用 `--save-records`。用户要求复盘时 `--review` 只读已有台账，未记录的不补造。**

## 温度筛选与压力测试

- 多档事件必须先核对完整档位分布（默认只展示用到与相邻档位，用户追问再展开全表），预筛（决定拉哪些盘口）与候选表使用同一口径（中心情景 `p_calibrated`），不能用悲观漂移下界 `p_min` 预筛，否则紧邻预报中心的档位（如中心 14.9°C 时的 15°C 档）会在取盘口前被静默丢弃。缺席档位不等于无边际。
- 压力测试只衡量假设敏感性，不是实际概率或普遍必要/充分盈利条件。所有 NO 使用同样的压力情景，包含零漂移，远离中心也不豁免，不为救回候选调规则。
- `--risky` 只展示诊断项；硬筛未通过须如实标注，不悄悄绕过或为凑推荐改门槛。另做独立研究须提供额外证据，并标明独立研究身份和原筛选失败，不能冒充脚本合格项。

## 输出与条件限价

默认中文，先结论后表格，理由用大白话。行序综合证据稳健性、条件回报、流动性与不确定性，**不另设排序列**；市场偏稳的条件方向与独立证据支持的价值方向分清，普通参考不冒充已验证高胜率。

### 默认：一张三列推荐表

先给 1–2 句结论，再给这张表。YES 和 NO 都覆盖：

| 买什么 | 买入价 | 赢了赚多少 |
|---|---|---|
| 🟢 城市·日期·最高/最低·档位·YES/NO | 当前可成交的 ask（分） | 赚 X¢ / +Y%（一眼看出回报） |

色标规则：🟢 模型市场一致（差 <1°C）；🟡 中度分歧或薄盘；🔴 显著分歧或证据不足。

表后最多 2–3 行：报价时间（UTC）、统一撤销条件、事件链接。模型中心、成交量、深度、费用、tick、完整档位、σ、压力测试等**不默认展示**，用户追问再展开。没有合格单时表只留一行”本轮无”加一句原因。

### 完整核对版（用户要细节或需要留证时）

| 状态 | 城市·日期·最高/最低·档位 | 方向 | 吃价/挂价·容量 | 天气预报模型/市场中心 | 盈利空间/依据 |
|---|---|---|---|---|---|

- 状态：**当前可考虑 / 等待限价条件 / 不参与**；纯观察单列，不凑推荐。方向明确买 YES/NO。
- “吃价/挂价·容量”：吃价是即时成本，挂价是价差内限价，容量写实际可买份数；报价缺失写未知。
- “天气预报模型/市场中心”：先市场分布/众数档、可靠时才给加权中心，再并列官方/各模型参考；缺数据或口径不可比写未知，差异不代表定价因果。
- “盈利空间/依据”：获胜毛收益 `1-c` 与毛投入回报 `(1-c)/c × 100%`；依据写可追溯证据及支持范围，多个来源一致不自动换成概率区间；无可靠数值写“未能可靠估计”。模型情景不充当真实胜率。默认表后和完整核对版都保留撤销条件、复核/到期时点。
- 费用已核实才写净边际，否则标毛值；单位期望 `p*v-c` 仅在 p 的身份与依据明确时作条件计算，见 `references/risk.md`。

### 怎么解释“市场为什么这么定价”

用户问“为什么市场押这一档”时，区分可观测报价与原因假说：

1. 市场：给真实档位报价、众数档与采样时点；完整且可比才算带口径说明的中心，开放尾档不擅自设代表值。
2. 证据：并列指定官方及各模型的发布时点、站点和中心，说明何者偏暖/偏冷，不把模型平均叫市场中心。
3. 因果：无可核验交易者信息或事件时序等证据，就写“定价原因无法确认；预报差异仅是可能解释”，不说市场一定跟随某模型。

例：“市场最贵的是 7°C 档；尾档和部分报价缺失，中心无法可靠计算。官方预报 5°C，某模型 9°C，存在分歧；无法确认市场受该模型驱动，也不足以直接推荐 5°C 档。”

先用真实 bid/ask、tick、价差与容量给有依据的近端限价；价差窄且成本合理可列当前可考虑，不强制折价。不设统一价格硬阈值，不把 0.60–0.90 当盈利定律；极高买价回报薄需权衡，1¢ 也不等于利润薄或值得买。

“挂远一点”指更低的买入限价，不是离预报中心更远的温度档。远端价仅在真实取得的成交历史/连续盘口支持时给出，注明时段和依据；无历史写“无触达依据，成交概率未知”，不机械减 2–5¢，不编造触达率或为此无限取数。限价受可解释的条件价值上限约束，bid 本身不证明便宜。未成交就是未成交，不保证 maker 费率；价格到达时重估证据与费用，失效则撤销。

## 术语翻译（第一次出现就用中文解释）

| 词 | 大白话 |
|---|---|
| YES / NO | 买“会发生” / “不会发生”；每份到期结算 $1 |
| bid / ask | 盘口最高买价 / 最低卖价；ask 是你现在买进的成本，bid 是你现在能卖出的价 |
| 价差 | ask − bid；越窄越容易按合理价成交 |
| VWAP | 按计划份数吃掉多层挂单后的平均成交价，不是第一档价格 |
| 吃价 / 挂价 | 现在就能成交的价 / 放进价差排队等成交的限价；挂价不保证成交 |
| 盈利空间 | 获胜毛收益 `1-c`；毛投入回报 `(1-c)/c × 100%`，分母为投入；不是期望收益或胜率 |
| 市场中心 / 众数档 | 明确档位/尾档/归一化后算的价格代理中心 / 同时点可比报价最贵档；缺数据不计算，不是真实概率或保证 |
| p_calibrated | 脚本按模型中心算的情景概率；名字叫 calibrated，但没有样本外校准，不是真实胜率 |
| 结算站 | 最终按哪个机场/气象站的 METAR 读数结算，例如上海 ZSPD、北京 ZBAA、纽约 KLGA |
| Kalshi | 美国 CFTC 监管的预测市场交易所，美元计价、每份 $1；和 Polymarket 是两家不同平台 |
| Polymarket | 加密 USDC 计价的预测市场，全球用户；天气盘多在这里 |

## 脚本与运行数据

天气扫描一律用 `scripts/pm_weather.py`（含 `--settle` / `--risky` / `--brief`），不手工拼流程、不为每个城市创建临时脚本。从 skill 目录运行，参数以 `--help` 为准。日期换成已核实的目标当地日，城市按当轮发现范围选择：

```bash
python scripts/pm_weather.py --date YYYY-MM-DD --only "$CITY_FILTER" --mode both --top 10 --brief
python scripts/pm_weather.py --date YYYY-MM-DD --min-event-vol 5000 --min-depth-shares 20
python scripts/pm_weather.py --log-pick "id=<已核实ID>,side=NO,price=<参考价>,label=<档位>,code=<结算站>,kind=high,date=YYYY-MM-DD"  # 仅用户明确授权记录时
python scripts/pm_weather.py --review            # 只复盘 --log-pick 记录过的单
python scripts/pm_weather.py --settle YYYY-MM-DD  # 仅已结束且指定源已发布的当地日
python scripts/pm_weather.py --bias
```

`--brief` 只输出“推荐速览”（脚本摘要不替代规则核对及撤销/时效简注；“盈利空间”须按上述毛收益口径解释）（买什么/吃价挂价/盈利空间/天气预报模型/成交量深度），完整 YES/NO 明细仍可用默认输出。`--min-event-vol` 和 `--min-depth-shares` 只过滤展示，不改变取数；成交量只描述流动性。`--min-win` 默认 0.55，只让推荐速览显示情景赢率 ≥55% 的边，0 放开（明细表不受影响）。`--log-pick` 仅在用户明确授权记录后把推荐写入 `picks.jsonl`（显式写盘，默认不用），`--review` 只读该台账并按指定结算源判输赢，不重扫全市场。

`pm_edge.py` 可作给定概率的条件算术，`pm_calibration.py` 用于可信样本验证；保留 `pm_scan.py`、`pm_barrier.py` 等现有脚本，不将其存在解释为本 skill 继续承接非天气研究。

默认缓存仅在当前 Python 进程内存中去重，进程退出即消失；默认 import / --help / 扫描 / --json / --settle 均不写业务文件，也不读取旧磁盘缓存充当新数据。用 `--cache-mode disk` 或 `PM_WEATHER_CACHE_MODE=disk` 显式开启磁盘缓存；`off` 禁用缓存复用。磁盘模式保留各请求 TTL，并受有效期上限168小时、容量256MB保护；`PM_WEATHER_CACHE_TTL_HOURS`、`PM_WEATHER_CACHE_MAX_MB` 可调整，零禁用留存。

预测快照、规则正文、HKO预报历史及待核验结算历史默认均不保存，仅当次命令加 `--save-records` 才保存；缓存 disk 不会顺带启用历史。需要留证时在扫描和结算命令分别显式加该参数；规则正文按哈希去重。推荐台账 `picks.jsonl` 只在 `--log-pick` 时写入，`--review` 只读它，不会因为复盘而生成新预测。`--bias` 只读已有历史，无数据如实报告，不从旧缓存重建预测，也不把 pending 当 verified。

仅显式写盘时才创建外置目录：Windows 默认 `%LOCALAPPDATA%/trading-skills/pm-weather/cache` 与 `.../data`（macOS/Linux 使用系统用户缓存/数据目录；`picks.jsonl` 位于 data 目录）；可用绝对路径 `PM_WEATHER_CACHE_DIR`、`PM_WEATHER_DATA_DIR` 覆盖。历史不随缓存淘汰，不迁移或删除既有缓存/用户记录，不读取安装目录旧缓存。离线回归使用 `python -B -m pytest -p no:cacheprovider -W error tests`，避免生成字节码和 pytest 缓存；接口与真实市场验证另计。

## 每次任务收尾

完成或中断都核对本轮创建的文件、子进程、服务器与浏览器标签页。只清理可确认属于本轮的一次性下载、探针和测试缓存；仅停止本轮启动且不再需要的程序/任务，关闭本轮专用标签页，不关闭用户原有程序或其他任务。默认不留业务数据；用户显式要求的记录与正式产物保留（`picks.jsonl` 属显式记录，保留），所有 `.mimosa/` 不动。不确定归属先保留说明；失败/取消也执行收尾，报告删除、保留、归档及仍运行项。命令优先用 `python -B`，避免字节码积累。

## 错误处理

- 网络错误时脚本会立即停止并报告失败的数据源（Polymarket/Kalshi/天气 API）；所有数据源均失败时退出码为 2，不生成报告；天气部分失败也以退出码 2 和 stderr 警告报告。保留通用扫描器的部分失败退出码 0 行为说明，不将其作为天气成功标志。
- Agent 遇到错误立即告知缺失，不把不完整结果当完整扫描；时间戳用实际扫描完成时间（UTC），不估计。
- prewarm 失败在 stderr 明确标注，不计入候选；单次取数超时为 40s。全城扫描在 IEM 不稳时仍可能超预算，不无限等待；改用 `--only "城市1,城市2"` 缩小范围，或报告观测源不稳、未在预算内完成，不静默生成残缺结果。
