# 天气研究：证据组织与条件挂单

本参考服务 `pm-weather`，优先最高温、最低温与逐日温度档位。偏好提问、预算、输出列与完整 book/ID 校验统一以 `SKILL.md` 为准；天气技术口径配合 `weather.md`。不再提供推文、奖项、体育或政治的分类打法。

## 1. 从市场到天气证据

先确定事件唯一身份与当地日期，再比较同一时点的完整档位市场分布、YES/NO 两侧执行成本与天气情景。不要先相信扫描器边际，再只找支持该方向的证据。

每个城市保留一份可追溯的简明证据记录：

| 内容 | 应记录什么 |
|---|---|
| 合约身份 | 平台、事件/市场 ID、两侧 token、标题、最高/最低温、目标当地日 |
| 结算规则 | 指定站点和来源、单位、边界取整、缺测/修订处理、实际规则链接 |
| 时间 | 查询时刻、预报发布/有效时刻、观测时间、当地日结束与结果发布时间 |
| 独立证据 | 站点匹配的官方预报/观测、集合来源、预报中心、剩余时段与缺口 |
| 市场基线 | 完整档位、两侧排序后 bid/ask、足额执行量 VWAP、费用与 tick |
| 判断 | 市场偏稳方向、独立价值依据、情景敏感性、失效条件；没有概率依据就不填数 |

来源优先合约指定的官方站点、气象部门和可追溯的集合产品。网格、机场或其他代理仅在注明身份及偏差后作辅助；不能取代指定结算源。当天新观测要结合尚未结束的当地日解释，不把当前极值当最终结果。

## 2. 发现范围与候选组织

用 `pm_weather.py` 做天气发现与扫描，按当轮活跃城市、目标日和来源可用性缩小范围；首批不足时依主文扩批。3–6 个是默认展示量，不是上限；不为凑数放宽证据身份或静默绕过硬筛。

同城、同日的相邻档位高度相关，不冒充分散机会。主表行序兼顾稳健性、条件回报、可执行性与不确定性，不增排序列；不参与和纯观察另列。完整档位分布与候选表用途不同：未进 shortlist 的档位仍可能存在，缺席不是无价值或已移除的证明。

用户复查旧方向时，对比“旧依据与时点→新观测/预报→判断变化”。若只有排名变化、没有实质证据，不能机械从 YES 翻到 NO；旧限价不当现价。

## 3. 条件限价示例

以下仅为写法示例，不是当前报价或可执行建议；实际价格、tick、容量与历史依据须当轮取得。

```text
对象：城市·YYYY-MM-DD·最高温·某档
方向：买 YES/NO
当前成本：本侧 ask 0.42；20 份完整阶梯 VWAP 0.43
近端限价：0.40，依据为当轮 bid 0.39 / ask 0.42、tick 0.01
远端参考：无触达依据，成交概率未知（未取得历史/连续盘口）
失效：新预报/实测使独立证据不再支持，或当地指定时点到达仍未成交
```

近端限价也受条件价值上限约束；不因在价差内就自动认定便宜。只有实际历史/连续盘口支持时才另给远端价，并附时段与依据。买入后赔率改善不代表事件胜率提高，成交可能来自新信息；到价或成交时仍需重读天气证据与费用。

“价格挂远”和“档位离预报中心远”是两回事，后者见 `weather.md` 的压力测试。压力结果只能写模型情景，不能标“压力后真实胜率”。

## 4. 其他天气与边界

降水、风速、积雪等仅在用户提出时按需研究：先核实测量量（累计/瞬时/极值）、站点、时间窗口、单位、阈值、指定来源和数据可获得性，再决定是否有足够证据。不能复用温度的分布假设、漂移幅度或极值单调性，也不承诺已有自动发现、校准或专用脚本支持；不足则明确不参与。

非天气事件不属本 skill。体育、宏观、政治、加密价格等流动性合约可转 `pm-liquid` 的已有只读流程；推文、奖项、票房等不再由本参考给出打法，不承诺其他 skill 有专用模型。

## 5. 机制参考

盘口占比仅描述挂单供需，不是人数、持仓、信心或事件概率；单快照不能证明动量。等份 YES+NO 配对须两侧 ASK 阶梯完整、费用与结算兑换一致；未知费用只标毛观察，非原子两腿仍有风险。详细公式和机制见 `mechanics.md`、`risk.md`，此处不重复。
