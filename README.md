# Trading Skills

面向 AI 助手的两个只读交易研究技能。输出条件化计划，不自动交易，也不保证收益。

- **pm-edge**：预测市场研究，优先天气与文化；明确事件日期，比较 YES / NO，先审计结算规则，再核对报价与费用。
- **trade**：BTC / ETH 技术与期权研究；区分行情快照、模型假设和可执行条件，不把指标或历史波动率比较直接当作买卖信号。

## 安装

将 `skills/pm-edge` 和 `skills/trade` 复制到助手支持的 skill 目录。在 MiMo Desktop 中可使用 `~/.config/mimocode/skills/`；通过插件页面确认已发现技能。不要同时安装同名的多份副本。

## 使用

- `/pm-edge 扫描明天的天气盘，同时比较 YES 和 NO，先给候选表和条件挂单计划。`
- `/pm-edge 只扫纽约、东京、香港，给我高胜率的 NO 侧机会。`
- `/trade 查看 BTC、ETH 的结构，先说明数据时点和缺失信息，再给条件计划。`

具体脚本参数以各脚本 `--help` 为准。运行数据工具需要 Python 及网络访问；不同交易所、地区和时间可能导致接口不可用。失败时必须报告缺失数据，不能填造价格。

## 天气温盘一站式扫描（v1.1 新增，v1.2 提速加风控）

`skills/pm-edge/scripts/pm_weather.py` 把「读规则 → 拉观测 → 建概率 → 读盘口」合成一条命令：

```bash
python scripts/pm_weather.py --date 2026-10-25 --mode both --top 10 --min-edge 0.05
python scripts/pm_weather.py --date 2026-10-25 --mode no --only KLGA,东京,香港
python scripts/pm_weather.py --settle 2026-10-24      # 第二天先结算昨天
```

- 输出即表格：城市中文名、市场（最高/最低温）、档位、模型胜率、买入价、赔率、2¢ 内深度、口语化依据
- 观测基准是 routine METAR（整点报文，排除 SPECI 和 5 分钟 AUTO 记录），与结算源一致
- 三模式（ECMWF / GFS / ICON）集合成员 + 各自的滚动偏差修正，同时报告保守和乐观读数
- 香港两个盘按天文台口径处理：官方 9 天预报做中心，Daily Extract 的网格偏差做误差，进档规则为向下取整（31.9 算 31°C）；当月摘录走 `dailyExtract_YYYYMM.xml`（滞后 1–2 天）
- 概率与价格的边际用真实 NO/YES 订单簿 VWAP 核算，**同侧** 2¢ 内深度不足 3 倍单量的档位会被剔除
- NO 侧带抗漂移门槛：±1.5°C 朝所卖档漂移后胜率跌破买入价 5pp 的"相邻档"默认过滤（`--risky` 查看）
- `--settle` 一条命令结算过去日期：各市场实际值、获胜档、扫描时模型中心的偏差

**速度**：观测/集合/前一天预报按时区分组批量请求（Open-Meteo 多坐标、IEM 每 6 站合并），冷启动约 1.5–2 分钟完成全部 82 个事件，热缓存秒级。

## 重要边界

- 高市场价格不等于已校准的高胜率；不同模型也可能高度相关。
- 当天最高温和最低温在当天结束之前仍可能改变；观测站、日期、精度和修订规则必须匹配合约。
- 未核实的费用、NO 侧报价、深度或期权结算规格，不能用于声称存在可执行套利。
- 限价不保证成交或 maker 身份；止损不保证成交价。部分成交、滑点、跳空和结算争议都可能造成损失。
- 报价快照和条件计划不是实时指令。没有资金规模与风险预算时，不输出假装适合用户的实际数量。
- 不包含自动下单、账户密钥、个人账本或对话记录。

## 验证范围

离线回归测试用于验证公式边界、日期处理和失败路径，不代表已经回测出盈利策略。公开接口冒烟测试只说明当时能够读取数据，不证明模型准确。

2026-10-23 的实盘校验记录：用 2026-10-22 已结算的 20 个天气盘验证观测口径（16 个完全命中，差异均可追溯到结算源口径不同）；对 6 个高流量城市做了滚动偏差回测（样本外 MAE 从 1.32°C 降到 1.00°C）。这些验证覆盖观测口径与偏差修正，不构成对模型预测胜率的证明；使用前应查阅对应平台官方文件和具体合约条款。

2026-10-24 的实盘教训：四笔相邻档 NO 三笔亏损/告危（华沙 6°、亚特兰大 70-71°、香港 31°），根因是 ±1°C 的预报漂移正好落在所卖档位。据此加入抗漂移门槛（回测可拦下其中两笔），并把每日 `--settle` 结算固化进工作流。
